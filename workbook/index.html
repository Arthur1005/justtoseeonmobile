After seeing the mark for Workbook A, I was in shock. How can I do better? I was quite confused. So I booked a consultation with Karen to have a clearer mind and direction for my Workbook B.

I also got other feedback, like an update with clearer indicators, background choice, and more. This consultation is very helpful. I have a very clear guideline on what I can improve on, and it opens up more ideas (like the moving cards), which I would very much like to see in this process.

1. Bouncing Effect

Instead of giving freedom for users to move around my cards, I decided to make them randomly move. This pay attribute to the old TV's no signal animation shown on the screen. One of my core memory is sitting in front of an old TV, and await for that rectangular box to hit one of 4 corners perfectly. That is pure joy, which we do not get easily nowadays.


2. PNG to WebP, MP4 to WebM

This process changed everything; it saved up memory; it renders a smaller file size, and it is the reason my Workbook B run smoother than Workbook A.

One of thing I could do better next time is make sure I was not recording in 4k resolution. 4k resolution videos take up too much space, as every 10-second video is roughly 1-5mb. Even if I convert it to WebP files, it would still be a large file for the website to load.


3. Mobile Responsive

In order to carry over the bouncing cards to mobile, I turn the website horizontally. This caused a little bit of JS coding (which again taking more space and loading speed), but it turns out pretty good. It is not as slow as the laptop, but some other elements like the return icon, enlarge functions needed to be change too. I also learned new functions like 'playsinline' and 'env(safe-area-inset-bottom)' speicfic in mobile and iOS-specific.

'playsinline' makes the video play in the spot that it is put in a Mobile browsers, it will not opens a external (popout) video player, which in my case, it will be vertical instead of lanscape View

'env(safe-area-inset-bottom)' is a CSS function that prevent content being covered by device inherent UI. Such as navigation bars, rounded corners, notches, browsers UI, and iPhone home indicator areas.


4. Brain Icon

One of the pieces of feedback I got during consulting with Karen is to update my current icon for accessing the description. So I find a GIF of a brain that changes colour, and I thought it’s a great representation of the title ‘words from my brain’, plus, the changing colour also draws attention to the user to click and see the description in it.
